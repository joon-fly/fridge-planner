# 🍳 우리집 메뉴 플래너 (fridge-planner)

냉장고 재고를 관리하고, AI와 채팅하면서 오늘 뭐 먹을지·이번 주 식단을 추천받고, 롯데마트 실시간 가격·재고까지 확인해서 장보기 목록을 짜주는 개인용 웹앱입니다.

## 주요 기능

- **재고 관리**: 육류/야채/기타 카테고리, 냉장·냉동 보관 방법별로 재료를 등록하고, 유통기한 임박 재료를 자동으로 알려줍니다.
- **메뉴 레퍼토리 관리**: 기본 제공 메뉴 + 직접 등록한 메뉴를 관리합니다. 메뉴 이름만 입력하면 AI가 카테고리·필요 재료를 자동으로 채워줍니다.
- **AI 메뉴 추천 채팅**: 현재 재고, 유통기한, 영양 균형(단백질원 다양화, 조리법 분산)을 고려해 오늘 메뉴·주간 식단을 추천합니다. Claude(Anthropic API) 기반입니다.
- **롯데마트 실시간 재고·가격 확인**: 선호 매장을 설정하면, 장보기 추천 시 그 매장의 실제 상품명·가격·재고를 조회해서 구체적으로 안내합니다.
- **첫 로그인 온보딩 투어**: 처음 로그인하면 재료 추가 → 메뉴 관리 → 매장 설정 → 메뉴 추천까지 실제 화면을 짚어가며 안내합니다. 헤더의 ❓ 버튼으로 언제든 다시 볼 수 있습니다.

## 기술 스택

- **프론트엔드**: 프레임워크 없는 순수 HTML/CSS/JS 단일 파일 (`index.html`)
- **백엔드**: Vercel Serverless Functions (`api/*.js`)
- **데이터베이스 & 인증**: [Supabase](https://supabase.com) (Postgres + Auth)
- **AI**: [Anthropic Claude API](https://www.anthropic.com) (`claude-sonnet-5`)
- **롯데마트 데이터**: 자체 호스팅 프록시 — [joon-fly/daiso-mcp](https://github.com/joon-fly/daiso-mcp) (Cloudflare Workers, [hmmhmmhm/daiso-mcp](https://github.com/hmmhmmhm/daiso-mcp)의 포크)

## API 엔드포인트

| 엔드포인트 | 역할 |
| --- | --- |
| `POST /api/auth` | Supabase 이메일/비밀번호 로그인 |
| `GET/POST/PATCH/DELETE /api/ingredients` | 재고 CRUD |
| `GET/POST/DELETE /api/menus` | 메뉴 레퍼토리 CRUD (기본 메뉴 + 내 메뉴) |
| `GET/POST /api/settings` | 선호 매장 등 사용자 설정 |
| `POST /api/chat` | 재고·메뉴·실시간 상품 정보 기반 AI 메뉴 추천 채팅 |
| `POST /api/suggest` | 메뉴 이름 입력 시 AI가 카테고리·재료 자동 추천 |
| `GET /api/lottemart` | 롯데마트 매장/상품 검색 프록시 (`action=stores`\|`products`) |
| `GET /api/stock` | 문래점 기준 롯데마트 실시간 재고 단축 조회 (`?keyword=`) |

## 직접 설치해서 쓰기

이 저장소에는 코드만 들어 있고 키나 데이터는 없습니다. 직접 쓰려면 아래 계정을 **본인 것으로** 준비해야 하고, AI 사용 요금도 본인 Anthropic 계정으로 청구됩니다.

- [Supabase](https://supabase.com) 프로젝트 (무료 플랜 가능)
- [Anthropic API 키](https://console.anthropic.com)
- [Vercel](https://vercel.com) 계정

### 1. Supabase 테이블 만들기

Supabase 대시보드 → **SQL Editor**에서 아래 SQL을 실행합니다.

```sql
-- 냉장고 재고
create table public.ingredients (
  id           bigint generated by default as identity primary key,
  user_id      uuid not null references auth.users(id) on delete cascade,
  name         text not null,
  cat          text not null default 'etc',       -- meat | veg | etc
  storage_type text not null default 'fridge',    -- fridge | freezer
  qty          numeric not null default 1,
  unit         text,
  created_at   timestamptz not null default now()
);

-- 메뉴 레퍼토리 (user_id가 null이면 모든 사용자에게 보이는 기본 메뉴)
create table public.menus (
  id         bigint generated by default as identity primary key,
  user_id    uuid references auth.users(id) on delete cascade,
  name       text not null,
  category   text default '한식',                 -- 한식 | 양식 | 일식 | 중식 | 기타
  meat       text[] not null default '{}',       -- 육류·어류·계란 재료
  veg        text[] not null default '{}',       -- 야채·두부·버섯 등 재료
  created_at timestamptz not null default now()
);

-- 사용자 설정 (선호 롯데마트 매장)
create table public.user_settings (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  store_name text,
  store_area text,
  updated_at timestamptz not null default now()
);

-- 보안: RLS를 켜고 정책은 만들지 않는다.
-- 브라우저에서는 DB에 직접 접근할 수 없고, 서버(api/*.js)가 service_role 키로만 읽고 쓴다.
alter table public.ingredients   enable row level security;
alter table public.menus         enable row level security;
alter table public.user_settings enable row level security;
```

기본 메뉴를 넣고 싶다면 `user_id` 없이 추가합니다.

```sql
insert into public.menus (name, category, meat, veg) values
  ('김치찌개', '한식', '{돼지고기}', '{김치,두부,대파}'),
  ('제육볶음', '한식', '{돼지고기}', '{양파,대파}');
```

### 2. 로그인 계정 만들기

앱에는 회원가입 화면이 없습니다. Supabase 대시보드 → **Authentication → Users → Add user**에서 사용할 이메일/비밀번호 계정을 직접 만듭니다.

### 3. Vercel에 배포하기

1. 이 저장소를 포크한 뒤 Vercel에서 **Add New → Project**로 가져옵니다. (빌드 설정은 기본값 그대로)
2. **Settings → Environments → Production → Environment Variables**에 아래 값을 등록합니다.

| 변수 | 설명 | 찾는 곳 |
| --- | --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL (`https://xxxx.supabase.co`, 끝에 `/` 없이) | Supabase → **Connect** 또는 Project Settings → Data API |
| `SUPABASE_KEY` | Supabase **service_role** 키 | Supabase → Project Settings → API Keys |
| `ANTHROPIC_API_KEY` | Anthropic API 키 | Anthropic Console → API Keys |

3. 저장 후 **Deployments → 최신 배포 → Redeploy**를 해야 환경 변수가 반영됩니다.

> ⚠️ `SUPABASE_KEY`에는 모든 데이터에 접근할 수 있는 service_role 키가 들어갑니다. Vercel 환경 변수에만 넣고, 코드·`index.html`·커밋에는 절대 넣지 마세요. 서버는 이 키를 쓰기 전에 항상 로그인 토큰으로 사용자를 검증하고, 본인 데이터만 조회하도록 되어 있습니다.

### 롯데마트 조회 서버에 대해

롯데마트 매장·상품 조회는 이 저장소 관리자가 운영하는 Cloudflare 워커(`https://lottemart-mcp.joon9296.workers.dev`)를 **그대로 사용하도록 코드에 고정**되어 있습니다 (`api/lottemart.js`, `api/stock.js`의 `BASE`). 따라서 따로 설정하지 않아도 동작하지만, 이 워커는 무료 플랜의 요청 한도를 모든 사용자가 나눠 쓰며 사전 공지 없이 중단될 수 있습니다.

안정적으로 쓰려면 [joon-fly/daiso-mcp](https://github.com/joon-fly/daiso-mcp)를 본인 Cloudflare 계정에 배포하고, 위 두 파일의 `BASE` 값을 본인 워커 주소로 바꾸세요.

## 로컬 개발

이 프로젝트는 프레임워크나 번들러 없이 정적 파일 + Vercel 서버리스 함수로 구성돼 있어서, 정적 파일만 볼 때는 브라우저로 `index.html`을 열어도 되지만 API 호출을 포함해 제대로 테스트하려면 Vercel CLI를 씁니다.

```bash
npm i -g vercel
vercel dev
```

## 배포

`main` 브랜치에 푸시하면 Vercel이 자동으로 배포합니다.

## 알려진 제한 사항

- 롯데마트 실시간 조회는 제3자 백엔드(롯데마트 자체 서버)에 의존하기 때문에 간헐적으로 실패할 수 있습니다. 실패 시 "재고 없음"이 아니라 "조회 실패"로 안내하고 일반 시세를 대신 보여줍니다.
- 매장 검색(`action=stores`)은 재시도해도 실패율이 상대적으로 높은 편입니다. 자주 쓰는 매장은 한 번 설정해두고 바꾸지 않는 걸 권장합니다.
